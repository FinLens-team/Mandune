# PandaAI 与 Bocha 集成边界

## 1. 文档状态

本文件区分三类状态：

- **资料已核验**：已与本任务提供并确认的供应商资料核对；不表示真实请求已经成功。
- **运行未核验**：尚无使用项目凭据完成的脱敏请求、响应和错误证据。
- **产品规则**：满懂对供应商结果施加的约束，不是供应商能力声明。

供应商能力只有在运行验收通过后，才能从“候选集成”写成“已接通”。不得在仓库中保存 Bearer token、完整私人持仓或含凭据的请求记录。

## 3. 职责分工

### PandaAI

PandaAI 是基金、ETF 和 A 股结构化数据的候选来源。每个被分析的字段必须保留资产身份、指标名、值与单位、市场观察时间、获取时间和接口来源。若某个方法不能提供这些最小证据，相关字段标为不可用或未核验，不能由其他字段推断成当前值。

`id269` 只能用于其已确认的 `get_fund_detail` 范围。更广的 SDK 方法必须分别完成运行验收，不能以 SDK 中存在方法名代替接口可用性证明。

### Bocha

Bocha 用于搜索与持仓相关的公告、政策、产品披露或其他事件。查询应限制在完成本次复盘所需的范围，并使用最小必要的 `count`。请求不得包含完整持仓金额、用户约束、身份、账户信息或工作区访问凭据。

Bocha 返回的标题、摘要、排序和聚合信息只形成候选事件。物质性结论必须定位并核验原始公告、监管机构、交易所、基金管理人、上市公司或其他权威一手来源，同时记录发布时间和获取时间。无法回到主要来源时，事件保持 `unverified`，不能支撑方向性建议。

## 4. 组合使用规则

1. 以 PandaAI 提供结构化市场和资产证据，以 Bocha 发现可能解释持仓变化的事件。
2. 两类结果都先进入供应商中立的证据记录，再交给分析层；分析结果不得依赖供应商专有字段名。
3. 结构化数据采用分析开始时可获得的最新完整交易日，不把盘中值或获取时间写成完整交易日观察值。
4. 同一事实出现修订或来源冲突时，保留各版本和来源，按分析契约降级。
5. 供应商失败时保留已确认持仓，禁止伪造当前值、用搜索摘要填行情或生成正常观象长笺。
6. 透明示例使用固定缓存的 PandaAI 结构化证据和已核验事件证据，必须展示接口或主要来源、观察时间、获取时间和缓存标记，且与实时集成验收分开。没有可核对的供应商响应来源时，只能标为测试 fixture，不能标为 PandaAI 缓存。

## 5. 运行验收门槛

PandaAI 上线前必须用脱敏测试资产证明：

- 项目凭据可鉴权，凭据只在受保护的服务边界使用；
- 五个列出的方法逐个记录可用、无权限或不适用，而不是整体宣称 SDK 已接通；
- 基金、ETF 和 A 股各有代表性样本，并记录不支持和身份含糊样本；
- 关键字段的名称、类型、单位、币种、观察时间、获取时间和空值语义已核对；
- 最新完整交易日、基金净值日期、修订与冲突的处理可验证；
- 限流、超时、鉴权失败、无数据和畸形响应均映射为类型化状态；
- 日志和错误记录不含凭据或完整私人持仓。

Bocha 上线前必须用脱敏查询证明：

- `POST /v1/web-search` 的 Bearer 鉴权和 `query`、`freshness`、`summary`、`count` 请求约束真实可用；
- `count > 50` 被本地拒绝，不依赖供应商容错；
- 响应字段、来源定位、发布时间、空结果、限流、超时和错误映射已核对；
- 至少一个候选事件能回到权威一手来源，且搜索摘要与已核验证据清楚区分；
- 查询和日志不含用户身份、账户详情、完整持仓金额或 Bearer token。

## 6. 产品级验收

- 实时分析使用的结构化字段都能显示来源、观察时间和获取时间；无法确认时明确降级。
- PandaAI 方法名存在但无运行证据时，界面和文档不声称该资产或指标已覆盖。
- Bocha 发现但未完成主要来源核验的事件不会支撑物质性结论或方向性建议。
- 供应商失败、限流、空结果、过期、含糊和冲突场景均不制造当前值，并触发有限、仅观察或不可用状态。
- 示例缓存与实时结果有清楚标签，示例成功不能替代 PandaAI 或 Bocha 的运行验收。
- 当前产品没有盘中、实时行情或持续监控承诺。
