# 每日复盘 V2 后端规格

- 状态：已确认，可实施
- Issue：#73
- 基线：`origin/main` 已包含 PR #72 的 Atlas 持久化与展示边界
- 优先级：本规格记录用户确认的 V2 行为；与旧 Demo 放宽模式或 Atlas 独立模型生成描述冲突时，以本规格为准

## 目标

用户主动发起复盘后，服务端围绕冻结的组合快照完成一条可追溯链路：

1. 解析最新完整交易日及前一交易日；
2. 从缓存或 PandaAI 获取 A 股、ETF、场外基金的结构化数据；
3. 用 Bocha 发现事件候选，并回到官方或可信来源核验；
4. 确定性计算今日变化、盈亏贡献、敞口、集中度、覆盖和缺口；
5. 组装版本化 `ReviewPacket`；
6. 通过一次 `step-explore` 调用生成理性报告、人格报告和一个 Atlas 候选；
7. 校验并保存不可变结果，再把候选交给 Atlas 的查重、复遇、外观和持久化边界。

不引入 Agent loop、模型工具调用或多 Agent 编排。模型不负责取数、缓存选择和金融计算。

## 页面结果

同一次模型响应提供分析页的全部生成内容：

- `persona_report`：长报告卡正面的人格叙事；
- `rational_report`：长报告卡背面的理性客观叙事；
- `atlas_candidate`：长报告卡底部的一张图鉴候选。

正反面使用同一份快照、证据、派生结果、结论和建议。报告正文不再包含独立“每日扫盲”段落，学习或趣味内容只由底部图鉴承载。

## 数据与失败规则

- “实时”表示触发时最新可获得的完整交易日，不承诺盘中行情。
- A 股、ETF、场外基金逐项处理；一项失败不阻断其他持仓。
- 部分市场数据失败时，只基于已取得证据生成，并保存具体缺口。
- 全部市场数据失败时不调用模型，返回可重试的不可用状态。
- Bocha 标题和摘要只用于发现候选；未读取或未核验的来源不能支持物质性结论。
- 官方公告、监管机构、交易所、基金管理人和上市公司优先；可信财经媒体为次级来源。

## 缓存

SQLite schema v4 新增：

- `market_observations`：按供应商、方法、资产类型、代码和交易日缓存观察值；
- `asset_profiles`：缓存资产身份与资料；
- `event_searches`：按规范化查询哈希缓存 Bocha 搜索；
- `event_candidates`：保存搜索候选和核验状态；
- `source_documents`：保存已抓取来源的等级、摘要和核验状态。

最近三个交易日的成功数据每天最多刷新一次；更早历史默认复用。失败记录使用短有效期。进程内相同缓存键使用 single-flight，SQLite 唯一键保证幂等写入。不可变复盘历史不是供应商缓存。

## PandaAI 边界

- Node 每次复盘最多启动一个 Python 3.12 批处理子进程。
- 子进程通过 stdin 接收不含凭据的 JSON，通过 stdout 返回规范化 JSON。
- 凭据只从子进程环境读取，不进入命令行、日志、fixture 或响应。
- 每次调用使用隔离认证目录；成功、失败、取消和超时后均删除。
- SDK、Pandas 和供应商异常类型不进入 TypeScript 领域契约。
- 每个资产和方法独立返回可用、空结果、不支持或失败状态。

## Bocha 边界

- 查询只包含完成本次复盘所需的公开资产身份和最小时间范围。
- 不发送持仓金额、个人约束、身份、账户信息、工作区定位或凭据。
- 每项持仓请求 3 至 5 个候选，组合去重后最多核验 10 个来源。
- `count` 在本地限制为 `1..50`；超时、限流、空结果和畸形响应映射为类型化状态。

## 确定性派生

模型调用前由应用代码计算：

- 当前和前一完整交易日观察值；
- 单项涨跌额与涨跌幅；
- 数据足够时的单项和组合当日盈亏贡献；
- 最大贡献项与最大拖累项；
- 资产类别和行业敞口；
- 单项、行业和前 N 项集中度；
- 四项约束与已知风险之间的关系；
- 缺失资产、缺失指标和供应商失败项。

缺少金额、份额、成本或权重时，不估算无法复算的贡献。

## ReviewPacket

`ReviewPacket` 至少包含：

- schema、prompt 和生成策略版本；
- 快照 ID、分析 ID、最新完整交易日和证据截止时间；
- 全部确认持仓和四项约束；
- 逐项市场观察、变化和贡献；
- 组合汇总、敞口、集中度和风险；
- 已核验事件与未核验候选；
- 覆盖、缺失项和供应商失败项；
- 可引用的 `fact_ids`、`event_ids`、`line_ids` 和允许出现的金融数字。

## Prompt Compiler

四份 FINAL skill 作为版本化原文资产保存，不直接修改：

- `持仓分析-skill`；
- `奶龙转述-skill`；
- `孙哥转述-skill`；
- `兜兜转述-玄学版-skill`。

调用优先级：

1. 应用级事实、安全和输出约束；
2. 核心持仓分析 skill；
3. 当前人格 skill；
4. Atlas 版本化生成策略；
5. `ReviewPacket`。

应用级约束覆盖 skill 示例中的预测、真实人物冒充、迷信暗示、精确交易引导或未提供数字。覆盖只发生在调用层。

## 单次模型输出

唯一目标模型为 `step-explore`。先 capability-test JSON Mode；不支持时仍使用同一模型，以提示词强制 JSON 并严格解析。

```json
{
  "schema_version": "generated-daily-review.v2",
  "rational_report": {
    "markdown": "...",
    "fact_ids": [],
    "event_ids": []
  },
  "persona_report": {
    "persona_id": "...",
    "markdown": "...",
    "fact_ids": [],
    "event_ids": []
  },
  "atlas_candidate": {
    "schema_version": "atlas-candidate.v1",
    "kind": "professional_term or meme"
  }
}
```

服务端在调用前用 `analysis_id` 稳定选择 Atlas 类型，并只允许响应返回该类型：50% `professional_term`，50% `meme`。同时传入当前工作区同类型卡片的最小指纹，后端仍执行独立查重护栏。

## 校验与持久化

展示或保存前必须校验：

- JSON、schema version 和 finish reason；
- 正反面引用存在且关键事实一致；
- 金融数字来自 `ReviewPacket` 允许数字清单；
- 人格与 `persona_id` 匹配；
- 不含精确交易指令、收益保证、代客操作、凭据、身份或 reasoning；
- Atlas 类型与预选类型一致；专业名词引用存在；趣味梗不冒充金融事实。

结构失败使用同一模型和修复提示最多重试一次。第二次失败后不展示未校验报告。若正反面已通过校验而 Atlas 子对象无效，报告仍可保存和展示，Atlas 记为无卡；Atlas 失败不能改写分析状态。

历史保存快照、证据、派生结果、`ReviewPacket`、模型、prompt、skill、Atlas 策略版本和已校验生成结果。历史重放不重新请求供应商或模型。

## 验收

- schema v3 数据库可原子升级到 v4，Atlas 数据保持可读。
- 缓存命中不调用供应商；缺失时请求并写回。
- 一批持仓只初始化一次 PandaAI 会话。
- 部分供应商失败仍能诚实生成；全部市场数据失败时模型调用次数为零。
- 一次 `step-explore` 成功调用返回正面、背面和一个预选类型 Atlas 候选。
- Atlas 不再发起第二次模型调用。
- 新数字、无效引用、错人格、错卡片类型、交易指令或畸形 JSON 不进入历史或 API。
- 正常、部分失败、全部失败、缓存命中、重试、超时、取消、复遇和历史重放测试通过。
- 仓库、日志、任务事件、fixture 和生成结果不含凭据。

## 非目标

- 盘中实时行情和持续监控；
- 自主 Agent 或模型工具循环；
- 自动切换到 `step-explore` 之外的模型；
- 修改前端页面、交互或样式；
- 修改四份 FINAL skill 原文。
