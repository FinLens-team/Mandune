# 满懂分析契约

## 1. 职责

分析契约把一个用户明确生成的组合快照，转换为一份可验证、可降级的每日复盘。它约束输入、证据、结论和模型边界，不规定模型供应商、框架、传输协议或存储实现。

## 2. 输入契约

一次分析请求冻结以下输入：

- `snapshot_id` 与创建时间；
- 用户逐行确认的完整结构化持仓清单，覆盖基金、ETF 和 A 股；
- 每行的资产身份、持仓规模依据、观察日期和明确的未知字段；
- 投资期限、近期流动性需求、可承受回撤和投资目标，包含未填写或 `unknown` 状态；
- 主题标识；
- 分析开始时间、证据截止时点和所采用的最新完整交易日。

“完整结构化持仓”指模型收到快照内的全部已确认行，而非只收到摘要或抽样。它不表示每个字段都有已知值；未知值必须以类型化状态保留。

原始截图、个人身份、联系方式、账户名称、账户号码、工作区访问凭据和无关截图文字不得进入分析输入。截图只负责产生待复核草稿，删除规则见 [`demo-v1.md`](./demo-v1.md)。

## 3. 证据契约

结构化证券数据通过已完成运行验收的数据适配器获取，相关事件通过已完成运行验收的搜索适配器发现。当前候选分别为 PandaAI 与 Bocha；候选名称不表示已经接通。搜索结果只是发现线索，物质性事件必须回到可定位的原始或权威来源核验后，才可以支持结论。供应商事实与验收门槛见 [`../integrations/pandaai-bocha.md`](../integrations/pandaai-bocha.md)。

ADR-0005 已选择 PandaAI 作为初始真实结构化数据上游，代表性 A 股和 ETF 历史路径已有脱敏 spike 证据；这不替代完整适配器运行验收。ADR-0006/0007 已确定框架中立的 OpenAI-compatible `ModelGateway` 及其初始服务端实现，但这些运行时选择不进入本契约的供应商类型或领域数据结构。

每项证据至少记录：

- 稳定的证据标识；
- 对应资产或组合范围；
- 指标或事件类型；
- 值、单位及规范化说明（如适用）；
- 原始或权威来源名称与定位信息；
- 市场观察时间或事件发布时间；
- 获取时间；
- `available`、`stale`、`ambiguous`、`unsupported`、`conflicting`、`rate_limited`、`failed` 或 `unverified` 状态；
- 会影响解释的限制、修订或冲突。

结构化行情与净值以最新完整交易日为基准。获取时间不能冒充市场观察时间，搜索摘要不能冒充原始来源，缺失值不能由模型补写。

## 4. 分析流水线

分析按以下可观察阶段推进：

1. 校验并冻结快照；
2. 解析资产身份与覆盖范围；
3. 通过已验收的数据适配器获取结构化数据；
4. 通过已验收的搜索适配器发现持仓相关事件并核验主要来源；
5. 计算可复算的组合暴露和约束冲突；
6. 形成结论、方向性建议、未知项和限制；
7. 生成主题叙事并校验输出契约；
8. 保存结果或返回有限/不可用状态。

**Demo V1 默认编排形态**为单个分析 agent 按上列阶段串行执行，而不是多 agent 编排团队。等待界面可以显示阶段、覆盖数量、等待、重试和失败（例如聊天气泡短句），但不得展示模型思维链。阶段状态必须来自真实任务状态，不能只按计时器播放。

## 5. 结果契约

结果状态只能是：

- `supported`：现有输入和证据支持复盘报告表达的全部物质性结论；
- `limited`：部分缺口使结论范围缩小，但仍有证据支持有限的方向性建议；
- `observation_only`：只能呈现事实、观察项和补数建议；
- `unavailable`：没有足够证据形成可展示的复盘报告。

前三种状态可以形成同一份复盘报告的数据；`unavailable` 显示原因和恢复路径，不伪装成正常结果。复盘报告数据至少包含：

- 组合快照、分析时间、最新完整交易日和证据截止时点；
- 持仓覆盖与未覆盖清单；
- 四项约束及未知状态；
- 结论列表；
- 方向性建议及触发依据；
- 证据引用；
- 未知、冲突、假设与限制；
- 与当前持仓直接相关的必要概念解释；
- 风险提示；
- 主题正面和理性证据背面所需的表现数据。

每项物质性结论必须引用至少一项确认输入、派生结果或已核验证据。内容需区分：

- `observed`：确认输入或带时点证据；
- `derived`：可从输入、证据和公开规则复算的结果；
- `generated`：模型生成的解释和叙事。

`generated` 不能成为 `observed` 的来源，也不能新增证据区不存在的事实、因果或确定性。

## 6. 模型输入与输出边界

模型可以接收：

- 快照中的完整结构化持仓；
- 四项约束及未知状态；
- 已规范化的证据和来源元数据；
- 可复算的派生结果；
- 允许的建议边界、输出结构和主题表现指令。

模型不得接收原始截图、身份信息、联系方式、账户名称或号码、工作区访问凭据、供应商密钥或与复盘无关的截图文本。完整持仓载荷不得进入默认日志、分析事件、公开资源或测试快照。

模型输出必须通过带版本的结构校验和内容边界检查。超时、畸形输出、缺少证据引用、越界交易指令或主题正面与理性证据背面结论不一致时，该次输出无效；有限重试后返回 `limited`、`observation_only` 或 `unavailable`，不得展示未经校验的部分文本。

## 7. 建议边界

允许的建议只表达定性方向，例如维持观察、暂停继续增加、降低集中暴露、提高可用资金关注度或等待数据确认。每项建议都要指出触发它的持仓、约束、派生结果或证据。

禁止输出精确金额、份额、仓位比例、价格点位、买卖日期或时刻，也禁止代客操作、收益保证、胜率承诺和持牌意见暗示。风险提示不能为越界建议免责。

主题只重写表现。对相同快照和证据，主题不得改变证据选择、派生结果、覆盖状态、风险判断或方向性建议。任何主题都不得把相关性写成因果，也不得用吉祥物语气催促交易。

## 8. 缺口与超时

缺失、过期、含糊、不支持、冲突或无法核验的数据保持为未知，并明确指出受影响的持仓和结论。四项约束缺失时仍可分析，但依赖该约束的个性化判断必须缩小或取消。

实时路径以 90 秒完成为目标，以 180 秒为硬截止。到达硬截止时停止未完成的供应商和模型任务；只有现有已核验证据足够时才生成有限结果，否则返回 `unavailable`。硬截止后迟到的响应不得静默改写已完成结果。

示例路径可以复用缓存的 PandaAI 结构化证据和已核验事件证据，但必须保留原始观察时间、获取时间、缓存状态和来源。缓存示例不得计入实时路径的 90 秒目标证明，也不得证明供应商实时可用。

## 9. 验收矩阵

| 场景 | 必须观察到的结果 |
|---|---|
| 全部持仓和证据可用 | 每项物质性结论均有输入或证据引用，建议保持方向性 |
| 一项约束未知 | 允许继续，依赖该约束的结论明确受限 |
| 部分资产不支持 | 资产仍在覆盖清单，组合结论不假装完整 |
| 行情过期或获取失败 | 不制造当前值；受影响结论进入有限或仅观察 |
| Bocha 只有聚合摘要 | 摘要不作为物质性结论证据，事件保持未核验 |
| 来源相互冲突 | 保存冲突关系并缩小结论，不静默选择有利值 |
| 模型收到输入 | 请求含完整结构化持仓，但不含原图、身份或账户详情 |
| 模型输出越界或畸形 | 不显示部分结果；有限重试后降级 |
| 主题切换对照 | 理性结论、证据、覆盖、风险和建议完全一致 |
| 180 秒硬截止 | 未完成任务停止，只有有限或不可用结果 |
| 历史重放 | 同一版本输入和证据得到同一理性结果，不采纳后来数据 |

主动查询不属于本契约。任何后续问答能力都不能通过复用本分析接口绕过证据、隐私或建议边界。

## 10. Demo 放宽模式（流式自由文本）

为在真实模型网关上稳定完成每日复盘，Demo V1 采用一条放宽的模型输出通道。它与第 6、7 节的严格结构化输出并存，不替换契约其余部分。

- **模型输出改为流式自由中文文本。** 服务端用流式（token 增量）方式调用模型，不再要求模型返回带版本 JSON schema、逐条证据引用或主题正反面一致性。模型如何组织语言、使用哪些输入由模型自行决定。
- **约束作为简单信息直接提供。** 四项个人约束（含 `unknown`/未决）作为普通提示信息直给模型，不做复杂 prompt 编排；缺失约束不用默认值冒充用户选择。
- **客观持仓事实可含具体金额。** 用户逐行确认的客观事实（含 `size_basis` 的原始规模/金额文本、观察日期、代码）可原样提供给模型。可复算的占比、覆盖与状态仍确定性计算。原始截图、身份、联系方式、账户名称/号码、工作区凭据和供应商密钥仍不得进入模型输入。
- **确定性结构外壳保留。** 覆盖清单、四项约束、派生结果、结论/建议外壳、风险提示仍由确定性管线生成并通过既有校验器；自由文本作为附加展示层，明确标注为模型生成（`generated`），不新增证据区不存在的事实。
- **建议边界仍适用于确定性结论。** 自由文本为解释性叙述，不构成精确金额、份额、比例、价格点位、买卖时点的操作指令，也不作收益保证或代客操作暗示。
- **传输为增量推送。** 服务端通过 SSE 将文本增量推送到客户端边生成边展示；断线或硬截止后，已保存的完整文本仍可通过结果接口一次性取回。畸形或空文本时降级为不展示自由文本，结构外壳与降级状态照常呈现。

第 8 节的缺口与超时、90 秒目标与 180 秒硬截止在放宽模式下同样适用。
## 11. A2A 深度复盘扩展

本扩展不改变 Demo V1 浏览器主路径。服务端可以额外公开一张 A2A 1.0 Agent Card，并通过 `HTTP+JSON` 接受一次性深度复盘任务。调用必须使用独立 Bearer 凭据；Agent Card、请求、响应和日志不得包含模型密钥、工作区 locator、Cookie、账户信息或原始截图。

### 11.1 输入

- 必须包含 1 至 4000 字符的自然语言任务；
- 可以包含一份 `PortfolioSnapshot`，但必须通过当前 `CONTRACTS_VERSION` 和 `validatePortfolioSnapshot`；
- A2A 接口不读取匿名浏览器工作区，不根据 `contextId` 恢复私人数据，也不保留跨请求模型记忆；
- 文本或数据中出现凭据、身份、联系方式、账户详情或原始截图时 fail closed。

### 11.2 受控循环

- 底座模型为比赛指定的火山方舟 `DeepSeek-Pro`，OpenAI-compatible 请求中的 `model` 固定填写 Endpoint ID `ep-20260708162855-pcf9x`；凭据只从服务端 `ARK_API_KEY` 读取；
- 最长总时限为 15 分钟，其中循环阶段最多使用 13 分 30 秒，剩余时间用于汇总已取得的上下文；
- 最多执行 8 个模型步骤；达到 `finalize`、步数上限、取消、失败或循环预算即停止；
- 工具只允许检查已提交上下文、通过已明确授权的数据源查询快照内资产的结构化行情、运行确定性派生和提交最终摘要；授权数据源未配置时必须记录类型化失败，不得回退未授权第三方；
- 工具参数、资产范围、证据状态和引用由服务端校验，模型不能访问任意 URL、供应商凭据或浏览器工作区；
- 循环不得改变观察事实、确定性派生、覆盖、未知项或建议边界。

### 11.3 输出

普通 A2A 调用返回一个终态 Agent `Message`，至少包含文本摘要和 `mandong.a2a.deep-review.v1` 数据 Part。数据结构包含：状态、模型展示名、提供商、Endpoint ID、开始与完成时间、停止原因、步数、工具轨迹、实际使用的 Skills、数据来源摘要、请求上下文摘要、已核验证据、派生结果、最终总结、未知项、限制和服务端固定风险提示。

模型只产生总结内容；A2A envelope、schema version、状态、时间、步骤、工具记录、Skills、数据来源、证据列表和风险提示由服务端装配。模型候选总结若包含隐私载荷、收益保证或精确交易指令则拒绝展示并回退到确定性汇总。模型或工具失败时仍使用已取得的上下文形成 `limited` 或 `unavailable` 终态，不展示未校验的部分生成文本。A2A 的 15 分钟截止不修改浏览器每日分析的 180 秒硬截止。

## 12. 图鉴后置生成契约

图鉴不属于八阶段分析流水线，也不是复盘完成条件。只有已校验结果保存到不可变历史后，应用层才可以启动独立的 15 秒后置任务；复盘终态和报告必须先可读取。任务不得重跑取数、事件搜索、派生、结论、建议或主题叙事，也不得回写历史结果。

- `unavailable` 不启动；其它三种状态可以从同一份已保存分析产生候选。
- 系统先按复盘 ID 可复现地以 50% / 50% 选择专业名词或趣味梗，只调用选中类型，整次最多一个候选且失败不回退另一类型。
- 专业名词候选必须引用当前分析允许的确认输入、派生或证据标识；趣味梗可以是 AI 虚构短内容，但必须标明为非金融知识，不视为市场事实或人物原话。
- 候选须通过版本化结构、长度、分类和建议边界校验。专业名词还须通过引用边界校验；畸形、越界、空内容或迟到响应均不展示。
- 模型生成前接收当前工作区同类卡片的最小指纹（ID、名称、别名、类别和核心含义），按版本化策略先判断同义与复遇；不发送卡片关联的完整持仓、约束或历史情境。后端仍独立执行名称、别名和语义护栏。
- 查重明确相同时只追加复遇；明确不同时新建；语义判断不确定时返回无卡。删除后未来复盘可以重新创建同类卡片。
- 日志和分析事件只记录状态与计数，不记录完整持仓、工作区凭据或未脱敏卡片情境。
- 图鉴任务失败、超时或存储失败不降低分析状态，也不删除或覆盖已保存复盘。
