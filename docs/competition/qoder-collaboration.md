# Qoder 协作证据

状态：`证据计划，待赛事期间填充`。本文定义如何如实回答 Qoder 赛道人机协作问题，不把工具使用记录自动解释为产品完成证据。

## 赛道口径

用户提供的最新工作副本包含以下评选权重：产品完整度 `30%`、智能体协作深度 `30%`、真实价值 `25%`、创新性 `15%`。两项申请问题是：

1. 项目解决了什么问题？目标用户是谁？
2. AI 承担哪些角色，人如何设计人与智能体的分工？

这份副本与 2026-07-23 本地官方赛道快照一致，但正式提交前仍须从实时 United Portal 或赛道群逐字复核。复核证据应保存 URL、核验时间和脱敏截图或导出。

## 人机分工原则

### 人负责

- 定义用户问题、产品范围、金融建议边界和隐私边界；
- 判断主题、信息层级和东方观象表达是否符合产品目标；
- 审核兜兜的固定身份、跨主题服饰/环境变化和“观察、解释、承认未知”的职责边界；
- 批准需求、关键技术选择和验收条件；
- 审查 Agent 产物，修改、拒绝或要求补证；
- 运行或见证最终验收，决定哪些主张可以进入提交材料；
- 对最终代码、材料、合规和现场演示承担责任。

### Agent 可以负责

- 从已确认契约拆分有依赖的任务；
- 在明确文件边界内编写产品、规格、实现和测试；
- 检查代码、交叉引用、失败态和未证实声明；
- 运行静态检查、测试、构建和浏览器验收并返回结构化结果；
- 整理脱敏的提交证据和可复现命令。

Agent 不决定真实用户需求，不把金融未知项补成事实，不展示思维链，也不替人作最终提交和交易判断。

## 可追溯工作流

每个重要交付使用同一条证据链：

| 字段 | 记录内容 |
|---|---|
| 目标 | 人确认的用户结果和非目标 |
| 输入 | 使用的规格、源码、fixture 和限制 |
| Agent 角色 | 该角色的责任边界和独占文件 |
| 依赖 | 前置任务、交付物和解除阻塞的证据 |
| 产出 | 分支、文件、commit 或只读发现 |
| 人工判断 | 接受、修改、拒绝或要求补证，附具体理由 |
| 独立验证 | 测试、构建、浏览器证据或评审发现 |
| 最终状态 | 进入最终分支的 commit 和仍未解决的限制 |

展示协作深度时，优先选择一条端到端任务，说明各 Agent 之间的真实依赖和产物如何组合。并行数量和 token 数量不是证据。

## 最低案例集

最终提交前至少准备以下真实案例；实际未发生的类型应如实说明，禁止事后编造：

1. **接受案例**：Agent 产出经人工审查后按原意进入最终分支，并有验证结果。
2. **修改案例**：人工指出业务、设计或安全问题，Agent 按要求修改，前后差异可定位。
3. **拒绝案例**：Agent 建议或实现因越界、缺证或不符合目标而被拒绝，记录拒绝理由。
4. **独立发现案例**：测试或评审 Agent 发现实现者未报告的问题，问题得到修复和复验。
5. **失败与恢复案例**：任务超时、会话中断或产出不可用时，保留状态并由新角色检查实际分支后继续。

该归档是**未验证的中断产物**：

- 不视为已接受实现；
- 不计入最终产品完成度；
- 不证明测试、构建、数据契约或用户流程通过；
- 不应合并到最终分支，除非后续逐项审查、迁移并在新 commit 中验证；
- 提交材料只能把它作为“失败与恢复”证据，并明确最终采用或拒绝了哪些内容。

## 评分证据映射

### 产品完整度（用户提供：30%，待复核）

- [ ] 完整首次使用不依赖预置结果或隐藏评委路线。
- [ ] 逐行确认、四项约束、不可变快照和 30 天历史均可操作。
- [ ] 固定熊猫角色兜兜跨主题身份一致，只改变服饰和环境，不预测吉凶或替用户决策。
- [ ] 示例数据、真实数据和缓存证据边界清楚。
- [ ] Agent 观测台、可翻面的观象长笺和 30 天工作区历史均为真实可交互界面。
- [ ] 正常态和有限态都通过端到端验证。
- [ ] 375px 触控和 AdventureX Expo 桌面环境均可完成核心流程。

### 智能体协作深度（用户提供：30%，待复核）

- [ ] 至少一条端到端任务显示多个 Agent 的明确角色、依赖和交付物。
- [ ] 有人工定义目标、审查结果和关键决策的记录。
- [ ] 有 Agent 产出被修改或拒绝的具体证据。
- [ ] 有独立测试或审查 Agent 发现问题并闭环的记录。
- [ ] Qoder 记录与最终 commit 能建立可追溯关系。

### 真实价值（用户提供：25%，待复核）

- [ ] 目标用户问题有真实、脱敏、经同意的证据，或明确标注仍是假设。
- [ ] 可用性任务证明用户能理解结论、找到证据和识别有限态。
- [ ] 不用功能数量代替用户结果。
- [ ] 不虚构访谈、留存、收益或准确率。

### 创新性（用户提供：15%，待复核）

- [ ] 解释观象长笺为何比资讯列表或聊天框更适合每日复盘。
- [ ] 证明东方观象叙事正面与理性证据背面共享同一分析版本。
- [ ] 证明 Agent 观测台提供真实阶段、覆盖、等待、有限重试和失败，而不是装饰性思考动画或思维链展示。
- [ ] 证明有限态是主流程的一部分，而不是额外错误页。
