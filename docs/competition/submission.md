## Portal 字段

### 作品名称

满懂

### 一句话简述

把年轻轻投资者的持仓、个人约束和带时点市场证据整理成一张可翻面核对的每日复盘长笺。

### 详细描述

年轻轻投资者能看到很多净值、涨跌和市场信息，却很难判断它们与自己的基金、ETF 和少量 A 股持仓有什么关系。满懂从用户确认的持仓和四项最小约束出发，筛选与组合相关的证据，生成一张东方观象风格的每日复盘长笺。

长笺正面先解释最重要的变化、它与组合的关系和方向性关注；用户可以翻到理性证据背面，逐项核对确认输入、证据时点、派生关系、未知项和限制。建议只表达暂停增加、降低某类暴露或调整关注方向，不给出精确金额、比例、价格和交易时点，也不替用户操作。

固定熊猫角色“兜兜”陪用户完成这次复盘。兜兜在不同主题中仍是同一个角色，只更换服饰和环境；它负责观察、解释和承认未知，不预测吉凶，也不替用户作决定。

Agent 观测台展示真实分析阶段、输入、覆盖、等待、有限重试和失败。它不展示模型思维链，也不把 Agent 活跃度包装成预测把握。数据缺失、过期、冲突或不支持时，满懂缩小结论并进入有限态；证据不足以支持方向时，只保留观察项和补数建议。

首次使用从普通入口完成主题选择、示例或自有组合复核、逐行确认、四项约束、不可变组合快照和分析生成。透明示例使用可复现的缓存证据并清楚标出来源、观察时间、获取时间、证据截止时点和缓存状态。`PandaAI-style` 只描述这种透明缓存证据的演示形态，不表示已经完成 PandaAI 集成。

## Qoder 赛道问题草稿

以下问题和权重来自用户提供的修订文案。虽然它们与 2026-07-23 本地赛道快照一致，仍须在最终 Portal 逐字复核。

### 1. 项目解决了什么问题？目标用户是谁？

满懂面向以基金和 ETF 为主要持仓、可能持有少量 A 股的年轻轻投资者。我们当前把“市场信息分散，用户难以把它与自己的持仓和约束联系起来”作为核心问题假设。产品把确认持仓、投资期限、近期流动性需求、可承受回撤和投资目标，与带时点证据放在同一次复盘中，帮助用户理解当前能得出什么结论、为什么，以及哪些判断仍受数据限制。

目标人群和问题范围是产品契约。真实需求强度、可用性和价值仍需由 [目标用户证据计划](../research/target-user-evidence.md) 中登记的真实、脱敏研究证据支持。在完成研究前，不声称已有用户普遍认可、留存提升或投资结果改善。

### 2. 人机协作工作流是什么？

人负责定义产品目标、金融建议边界、隐私要求和验收条件，并审查、修改或拒绝 Agent 结果。Agent 按明确输入和交付物承担需求核对、产品与设计文档、实现、测试、代码审查和证据整理等角色。每项工作通过任务依赖、分支、commit、测试结果和人工决定建立可追溯关系。

最终答案必须替换为赛事期间实际发生的协作记录，至少包含一个人工修改或拒绝 Agent 产出的具体例子，以及一个独立测试或评审发现问题并闭环的例子。Agent 数量、聊天长度和生成代码行数不构成协作深度。

## 可验证亮点

这些亮点只有在最终分支中可操作并通过录屏或浏览器验收后，才能使用完成时：

1. 一条完整首次使用流程产生绑定组合快照和证据截止时点的观象长笺。
2. 东方观象叙事正面和理性证据背面引用同一分析版本，主题不改变计算和结论。
3. 兜兜跨主题保持同一身份和职责，只改变服饰与环境，不预测吉凶或替用户决策。
4. Agent 观测台可交互地展示真实阶段、覆盖、等待、有限重试和失败。
5. 正常态与有限态都从普通产品路线到达，不依赖隐藏评委页或开发工具。
6. 30 天工作区历史能区分旧快照、旧证据截止时点和当前状态。
7. 核心流程可在 375px 触控视口和 AdventureX Expo 桌面环境完成。
